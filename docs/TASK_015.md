# TASK_015.md

# Phase 7 – Response Formatter

## Status

Planned

---

# Objective

Implement the Response Formatter for CyberRAG.

The Response Formatter converts the raw response generated by the LLM into a structured, user-facing format while preserving traceability to the retrieved CVE evidence.

This task is strictly backend-only.

---

# Background

TASK_014 introduced the LLM Interface, which returns the raw output generated by the configured language model.

Raw model responses are inconsistent and may lack structure.

The Response Formatter standardizes the output before it is returned to downstream components or API consumers.

---

# Scope

Implement:

- Response formatting
- Source attribution
- Confidence representation
- Metadata preservation
- Structured output

Do NOT implement:

- Retrieval
- Prompt generation
- LLM inference
- Streaming
- Conversation memory
- Frontend changes

---

# Functional Requirements

## Input

Accept:

- Raw LLM response
- Retrieved documents
- Metadata

Example:

```python
format_response(
    llm_response,
    retrieved_documents
)
```

---

## Output

Produce a structured response containing:

- Final Answer
- Referenced CVEs
- Source metadata
- Confidence (if available)

Example:

```text
Answer

...

Sources

- CVE-2024-1234
- CVE-2024-5678
```

---

## Source Attribution

Preserve the relationship between the generated answer and the retrieved documents.

Never invent sources.

Only include sources supplied by the retrieval pipeline.

---

## Formatting

Responses should be:

- Deterministic
- Human-readable
- Consistently structured
- Easy to consume by APIs

---

## Metadata

Preserve:

- CVE IDs
- Severity
- CVSS
- Published date

Do not discard metadata required for future API responses.

---
